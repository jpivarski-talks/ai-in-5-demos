## Demo 1: Optimization

Suppose we want to design a slide that minimizes the time a ball is rolling down it (the brachistochrone problem). This demo should have a large window containing a simulation of a ball sliding down a line due to gravity. The line has upper-left and a lower-right endpoints and 15 nodes equidistant in horizontal spacing with variable heights: the slide is a linestring with nodes that have fixed $x$ positions. The ball should be simulated with finite width, real momentum, no air resistance, a constant downward force, and a normal force perpendicular to a slighly smoothed version of the slide. (The smoothing should be too small to notice, but avoid abrupt changes in angle at the nodes.) The ball can't bounce, so don't make presets that look wrong with this non-physical constraint.

In the first page of this demo, I'll just be showing the simulation. There should be a few presets for linear slope, ski jump, two hills, and immediate drop. There should be a conspicuously large timer counting the number of seconds with millisecond precision from release from the upper-left to crossing the right edge. All of the presets should be such that it never takes more than 5 seconds, and the optimum (the cycloid) should be about a second or less. Below the timer (bottom-right), there's a "history" bar chart that shows the final time of all presets tested. Whenever the ball reaches the right edge, the timer stops and a new bar appears in the chart (without moving the previous bars). The history has a fixed vertical scale, which needs to be set appropriately.

In the second page of the demo, I show random slide shapes (generated by random Chebyshev polynomials so that they're smooth, but presented as a linestring). With each random slide shape, the simulation is computed but not shown: only the time is presented with the same big timer as in the first page. Now it doesn't count up: it just shows the answer. The "history" bar chart is empty at the start of the second page and each new random slide shape appends a new bar to the history. The window has room for the last 30 cases and scrolls when I get to the far edge.

In the third page of the demo, the widget uses an optimization algorithm (one that doesn't need gradients) on the 15 parameters, starting at a random shape, to minimize the time. Simulations are not shown, but each iteration of the slide is shown with its simulated time so that we can see how the minimizer searches the space of slide shapes and eventually arrives at the cycloid. Iterate in enough small steps that the evolution takes a few seconds. The history of times is now a line plot instead of a bar chart, but its style should make it clear that it has the same meaning as before. Instead of scrolling when it gets to the end, it starts zooming to keep the whole history in view. The button that generated a random shape in the second page now generates a random shape, clears the history, and starts the optimization.

I'll be presenting this as a very early example of "design by optimization" ("farming", rather than "craftsmanship", following my example on page 74 of @"DSI_ AI Development Program Lecture 1.pdf".

## Demo 2: Compression

Suppose we want to compress an image by approximating it and saving just the approximation. First, I'll need to show how fitting functions to a curve works in general.

The first page shows 1-dimensional data that has an interesting shape. It's a $y$ versus $x$ plot of data points with uniform $x$ spacing. Behind the scenes, the first 8 Fourier components are computed, and the shape of the data to fit is such that the 8 Fourier components are a pretty good fit, but not a perfect fit. Perhaps the data could be generated from random Fourier compoents plus noise (which would mean that the Fourier compoents are already known and don't have to be fit), or maybe the data could be generated from a random walk. Overlaid on the data is a "fit" line, which is initially just a horizontal line (the mean $y$ of the data; the constant of the Fourier series). When I press the first of 8 buttons, the first component (a sinusoidal curve with the biggest wavelength) descends from above until it reaches the middle of the plot. Then it disappears and adds to the fit function. The second button brings down the next component, and so on, until I've pressed all 8 buttons and we get our best 8-component fit. (Once each button is pressed, it's greyed out because the component is already included.) I'll be calling these Fourier components "templates" because their shape is fixed, but their amplitudes are just what they need to be to add up to a good approximation of the data. There's another button for clearing the fit and making a new random dataset.

The second page shows a square greyscale image. We'll use the same image for everything, but it should be a public domain image that looks good in greyscale and has some regions with high detail and other regions that are mostly uniform—maybe a noir detective. (The image should be selected after the machinery is in place so that we can pick an image that demonstrates the argument well.) The image is in one box and there's another box of the same size beside it. When I press a button, the second box is filled with a single vertical and a single horizontal Fourier component. A second click adds the second component, and so on until I've clicked 10 times and then the display auto-advances through many components until it gets something that's a good fit, a reasonable approximation of the original image. As every new component is added, a loss versus step line graph (with the same style as the brachistochrone time versus iteration) records the history of the pixelwise sum of squared differences between the images. The loss decreases as the fitted image approximates the original image better. I'll want to point out that the broad, flat regions of the original image have small waves in the fitted approximation. A button that brings up a new window in front of everything else showing the contrast-normalized difference between original and fitted would help me make this point. I'll mention that this is how JPEG compression works (roughly).

In the third page, I'll introduce adaptive basis functions. This page is 1-dimensional $y$ versus $x$ again, but instead of sinusoidal curves with fixed wavelengths, I have 3 logistic functions. A panel on the right shows the data and the sum of the 3 logistics, and the left is divided into 3 vertical panels with one logistic in each panel, each with handles for me to manually drag the $x$ offset (a handle in the middle), the asymptotic value (a handle on the curve at the far right of the plot), and the transition width (a handle a the point on the curve where it reaches 90% of its height). As I reparameterize the logistics, their sum overlaid on the data in the right panel moves with them. Then there's a button that automatically optimizes the adaptive basis functions to fit the data, slowly enough that we can see it happen in real time (a few seconds). The shape of the data should be chosen such that 3 logistics are a pretty good fit, but the shape of this dataset should be chosen in the same way that the shape of the data were chosen on the first page: it should be some data generation routine that makes data that's as good for Fourier fits as for 3-logistic fits. This page also needs a way to randomize the data and reset the logistic parameters.

The fourth page returns to the problem of fitting the same greyscale image. It has the same two panels (original image and current fit) and loss (pixelwise sum of squared differences) versus iteration history. The difference is that instead of fitting it with a Fourier series, we're fitting it with adaptive basis functions. On this 2-dimensional plane, the functions are a little different:

  f(x, y; x₀, y₀, θ, s, ℓ, A) = A · tanh(s·u) · exp(−v² / 2ℓ²)

with u = (x−x₀)cosθ + (y−y₀)sinθ and v = −(x−x₀)sinθ + (y−y₀)cosθ. Each f is a function of x, y parameterized by x₀, y₀, θ, s, ℓ, A. Parametrize s = exp(ρ) and ℓ = exp(λ) so they stay positive, and leave θ unbounded. (The symmetry (θ+π, −A) ≡ (θ, A) is harmless.) Normalize coordinates to [−1, 1] and optimize the summed squared pixel error with Adam. Initialize x₀, y₀ so that they're uniform across the image but start ℓ values large enough to feel the whole image so that none of the functions get stranded in a flat region with zero derivative. Pick the right number of functions (and the image!) to converge quickly enough for us to see it in the animation, using fewer parameters than the Fourier example on the second page, at a similar level of approximation.

After running this and maybe resetting it and running it again, I'll say that this use of adaptive basis functions is exactly what a neural network is for one hidden layer. Then, back in my main deck of slides, I'll present neural networks with the biological neuron analogy as a historical introduction, then emphasize that a single hidden layer neural network is exactly the thing we just built to approximate data and only has a passing resemblance with what happens in human brains.

## Demo 3: Generalization

The first page is a 2-dimensional plane of orange and blue data points to classify. The distribution of data points consists of a few noisy, partly overlapping blobs (maybe XOR?), and the model (a single hidden layer neural network with a huge number of hidden neurons) overfits the data conspicuously, forming islands around individual data points (the model is visualized by coloring the plane, similar to https://playground.tensorflow.org). A button resamples the data from the same probability distribution but doesn't change the model, so I can show that the model was a good fit to the exact data points, but not a good fit to the process that generates data like that. Another button resets the model with random parameters and a third starts a new optimization. As usual, there's an in-sample loss versus iteration plot (solid line), but this one also has a grey dotted line representing out-of-sample loss versus iteration, which I'll explain.

The second page is similar, but its data problem is one class of points as a disk and the other class of points as an annulus around the disk, both with much less noise. The minimal neural network necessary to fit (1 hidden layer with 3 neurons) is shown, with a network diagram connected by lines indicating weights, just like https://playground.tensorflow.org/#activation=sigmoid&batchSize=10&dataset=circle&regDataset=reg-plane&learningRate=0.03&regularizationRate=0&noise=0&networkShape=3&seed=0.23579&showTestData=false&discretize=false&percTrainData=50&x=true&y=true&xTimesY=false&xSquared=false&ySquared=false&cosX=false&sinX=false&cosY=false&sinY=false&collectStats=false&problem=classification&initZero=false&hideText=false . It fits from a random state pretty quickly. This page has a button to stop the optimization and pop up a window showing how the first layer transforms the space, as discussed in https://colah.github.io/posts/2014-03-NN-Manifolds-Topology/ . The 3-dimensional plot is one that I can rotate by hand to find the angle that shows the separation.

The third page attempts a difficult problem, 3 spiral arms of different classes, but it uses the neural network of https://gist.github.com/jpivarski/f99371614ecaa48ace90a6025d430247 (but the network diagram is schematic, without live weights, because one layer has 100 nodes) and it shows the optimization in one panel next to an equal-sized panel that shows the transformation that the first layer performs, like the last output of the gist. At the start of the optimization, the transformation is close to being the identity, so the space doesn't start very twisted. Perhaps it can't start exactly at the identity and still find a good fit, but the parameters can be chosen to make the initial transformation mild. I will then describe how each layer of a neural network warps the space seen by the next layer in a way that's useful for finding symmetries in the data, rather than memorizing points. Today's deep learning models can be hundreds of layers deep, so they find lots of subtle structure.

## Demo 4: Words and Attention

This demo might be able to use a fully trained, off-the-shelf model. I'll need a model that translates English to a language well-known to the audience with matching gender and word-order difference from English (e.g. French or Spanish), and the model must have exactly one attention head. The attention head and the English word embedding must be accessible programmatically. It also needs to be easy to run in inference mode on a MacBook with no GPU. It does not need to run in JavaScript; I can start a localhost Python server on my MacBook during the presentation. If no such model exists on HuggingFace, you can find some datasets, use this computer's GPU to train one. If you have to train a new one, use individual words as tokens.

The first page will illustrate the embedding. I'll type a word in a text field, press enter, and its vector will appear below it as an array of floats with sufficient rounding that it's not too big on the page. Then I'll type a different word and see a different vector. In a panel below it, the word will appear as a dot labeled by the word in the center of a plot. In the background, we search for the 15 closest words in the embedding (they can be in a kNN data structure), compute the first 2 PCA components of their distribution, and put those on the same plot with the target word, all as labeled dots (with axes scaled so that all the points can be seen). Thus, for every word I type in the text field, we'll see the words that are closest to it semantically in an appropriate geometric arrangement.

The second page will illustrate cross-attention. I'll type an English sentence in a text field, press enter, and its translation will appear below it. In addition, a matrix will show the strength of the cross-attention weights between the words/tokens of the two languages, like Figure 3 of https://arxiv.org/abs/1409.0473 . I'll point out examples with reversed word order, such as French adjectives, and examples in which an English word attends to more than one word in the other language in order to match gender between nouns and articles or between nouns and adjectives.

I'll explain that this attention mechanism was the key to building a language model that can make connections between words that are arbitrarily far apart in its context window.

## Demo 5: Few-Shot Learning

This demo will use an off-the-shelf LLM through a OpenRouter key. It needs to be a base model, trained on large textual datasets, but with no post-training. Given a prompt, it should literally complete it, rather than try to answer the question. If OpenRouter doesn't have base models, I'll need to host one somewhere, either on a paid server or on the MacBook for the presentation (I hope I don't have to do that).

The page consists of one big text box. I can edit the text and then press a "complete" button and it will submit it as a prompt for completion and stream back the result in the same text box, literally completing the text, but the completion is in blue. A few buttons on the side replace the text box content with preset prompts to do various few-shot learning problems:
* country → capital, element → symbol, word → antonym
* translation to and from the same language as in Demo 4, but this model *wasn't trained for that*
* classical syllogisms, like "All men are mortal. Socrates is a man. Therefore, ____," but with examples that certainly weren't in the training data (to show that it generalizes)
* invented rules, such as ordering English sentences with the verb at the end ("The cat on the mat is.") or turn prepositions into postpositions ("The cat is the mat on."), something that is unlikely to have appeared in the training data

The point of this is to show the transition from the small demos in this lecture to LLMs, which they're familiar with. I feel like few-shot learning is right on the cusp of that.
* Like Demo 1, an LLM is built from an objective-minimization principle: it's optimized (pre-training) to predict the next word/token in a sequential dataset.
* Like Demo 2, an LLM is a compression of the training data it was given, an approximation of trillions of words of human-generated text.
* Like Demo 3, an LLM doesn't simply memorize that text; it generalizes it. Many layers transform and re-transform the words' embedding space to find subtle symmetries and relationships in the text.
* Like Demo 4, an LLM is able to connect distant words in a sequence (as long as they're both within the context window), thanks to the attention mechanism.
* Like Demo 5, an LLM is a solver of a broad set of problems, including those that it was not explicitly trained for. The only mysterious element in this machine is the giant corpus of human text: there's enough structure in its symmetries and interrelationships that it has encoded human ways of thinking, and those ways of thinking can be played back in new situations to solve new problems.
